# Issue

**Title:** Fix PR size labeler on fork PRs

## Description

Switches `.github/workflows/labeler.yml` from `pull_request` to `pull_request_target`.

PRs from forks get a read-only `GITHUB_TOKEN` under `pull_request`, whatever the `permissions:` block says. As a result, fork PRs (e.g. #771, #767, #774, #758) have never been labelled. Older runs show the same 403 (`Resource not accessible by integration`), but `codelytv/pr-size-labeler@v1` used to swallow it and exit 0. A recent update to the floating `v1` tag now fails the step on API errors, so the check went red.

`pull_request_target` is safe here: the job never checks out or executes PR code. It only reads the diff size and writes labels via the API.

Note: `pull_request_target` uses the workflow file from the base branch, so this only takes effect for open fork PRs after it is merged into `dev`.
