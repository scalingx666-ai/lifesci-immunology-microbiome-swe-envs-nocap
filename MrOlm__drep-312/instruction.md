# Issue

**Title:** Release 4.0.3: --primary_skani_min_af_both for plasmids (issue #311)

## Description

## Summary

Adds an opt-in `--primary_skani_min_af_both` flag that stops plasmid datasets from collapsing into one giant primary cluster (#311). Also bumps the version to 4.0.3, which publishes to PyPI automatically on merge.

**The problem.** A pair becomes a primary-clustering edge if its aligned fraction passes `--primary_skani_min_af` in *either* direction. Plasmids share mobile elements, and a small plasmid that is mostly a transposon or resistance cassette aligns ~100% to every larger plasmid carrying it. Under single linkage, a few of those plasmids chain thousands of unrelated plasmids together.

In #311, 27,237 *Acinetobacter* plasmids ended up in 1 primary cluster. Secondary clustering then built every pair in it: 741,854,169 = 27,237² Ndb rows. That step is single-threaded and was still running after 22 h at 350 GB of RAM.

**The fix.** `--primary_skani_min_af_both` requires the aligned fraction in both directions. This doesn't change the final clusters, as long as `--primary_skani_min_af` ≤ 100 × `--cov_thresh` and `-pa` ≤ `-sa`:
- Secondary clustering zeroes the ANI of any direction aligning ≤ `--cov_thresh`, then averages the two directions.
- So average linkage can only join two groups if at least one pair between them is within `-sa` and aligns in both directions.
- Any such pair is a primary edge under the new rule, so primary clustering never separates genomes that secondary would group.

The flag is opt-in because the either-direction 15% default was tuned to reproduce the Mash partition on UHGG.

- `drep/d_cluster/union_find.py`: `cluster_edges(..., cov_both=False)`, plus a vectorized `_reverse_coverage` that looks up the other direction's aligned fraction. A pair with only one direction present fails the both-directions check.
- `drep/d_cluster/compare_utils.py`: passes the flag through, and the log line says "in both directions".
